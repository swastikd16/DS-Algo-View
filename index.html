Order (M) Invariant Checklist
  • All non-root nodes satisfy [minKeys .. maxKeys] bound
  • All leaf nodes are at identical uniform depth
  • Keys in all nodes are strictly sorted in ascending order
  • Internal nodes with k keys have exactly k+1 children

Order (M) Capacity Formulas

For a B-Tree of order M:

  • Max children = M
  • Min children = ⌈M / 2⌉ (non-root internal)
  • Max keys in node = M - 1
  • Min keys in non-root = ⌈M / 2⌉ - 1
  • Root keys = [1 .. M - 1] (if non-empty)

Splitting Animation (Node Overflow)

When a node receives its M-th key (overflow), it splits around the median index ⌊M / 2⌋. The median key is promoted ↑ upwards to the parent, creating left and right sibling nodes.

Deletion Paradigm Comparison

You can toggle between two algorithms in the top toolbar:

  • CLRS Top-Down (Cormen): Preemptively borrows or merges on the way down whenever a child has ≤ minKeys. Guarantees single-pass deletion without backtracking (used by Cormen / CLRS exams).
  • Standard Bottom-Up (Reactive): Only borrows or merges if a leaf actually underflows (< minKeys). Minimizes structural changes (standard university lecture notes).

CLRS Deletion Cases (Cormen Chapter 18)

  • Case 1: Key in leaf → directly remove key.
  • Case 2a: Left child has > minKeys → swap with predecessor.
  • Case 2b: Right child has > minKeys → swap with successor.
  • Case 2c: Both children have minKeys → merge children with key.
  • Case 3: Descent child has ≤ minKeys → preemptively borrow from sibling (3a) or merge (3b) before descending.

Uniform Leaf Depth

All leaves reside at the exact same depth from the root, guaranteeing logarithmic O(log n) performance.
